# Dofek watch app

The Dofek watchOS companion records motion and relative-altitude samples, then
queues compressed files for transfer to the paired iPhone. The screen shows
sensor availability, recording state, pending sample counts, phone reachability,
and manual recording and sync controls.

## Runtime behavior

- `CMSensorRecorder` collects accelerometer data, including supported
  background recording.
- `CMMotionManager` and `CMAltimeter` collect gyroscope and relative-altitude
  samples while the app is active.
- `TransferManager` merges nearby accelerometer and gyroscope samples,
  compresses the payload, and queues it with `WCSession.transferFile`.
- `WatchSessionDelegate` activates the session and handles requests from the
  iPhone companion.

Apple documents sensor availability and delivery constraints in
[Core Motion](https://developer.apple.com/documentation/coremotion). File
transfers between the watch and phone use
[Watch Connectivity](https://developer.apple.com/documentation/watchconnectivity).
The UI reports unavailable hardware instead of assuming every watch supports
every sensor.

Authorized accelerometer recording persists its requested deadline, capped at
the [12-hour Core Motion recording limit](https://developer.apple.com/documentation/coremotion/cmsensorrecorder/recordaccelerometer(forduration:)).
The native Watch session publishes that recording window through
[`updateApplicationContext`](https://developer.apple.com/documentation/watchconnectivity/wcsession/updateapplicationcontext(_:))
after recording starts, account cleanup, and session activation. Gyroscope and
altimeter capture independently publish their current native start dates in
the same context when they start, stop, or fail. These dates are each
recorder's canonical in-memory state, sampled on the main thread by
[the native publisher](WatchSessionDelegate.swift); they do not require an
accelerometer recording window. The
[context builder](WatchAccountStateStore.swift) excludes disabled account sync
and recording that started at or before the account-erasure cutoff.
Both foreground collectors use a shared
[callback fence](WatchRecordingCallbackFence.swift) so callbacks from an older
recording cannot append after account purge or stop a newer recording. Buffer
append and purge share the fence lock; native sensor controls run outside it.

The iPhone uses the latest received, unexpired accelerometer window for
collection-closure warnings even while the Watch is unreachable. Foreground
gyroscope and altimeter start dates additionally require an activated,
paired, installed, currently
[`reachable` Watch session](https://developer.apple.com/documentation/watchconnectivity/wcsession/isreachable).
An unreachable Watch or missing/delayed application context cannot confirm
foreground capture. An old recording-start flag or pairing alone is insufficient;
see the [iPhone activity reporter](../../modules/watch-motion/ios/WatchCollectionActivityReporter.swift).

## Project integration

`expo-target.config.js` declares the watch target, deployment target, bundle
identifier, and required frameworks for `@bacons/apple-targets`. The iOS project
is generated by Expo prebuild; do not edit generated Xcode project files. See
the [mobile development guide](../../README.md#ios-simulator-development-build).

`Info.plist` contains the target-specific motion usage description. Target
build settings come from `expo-target.config.js` through prebuild.
`DofekWatchApp.swift` starts Sentry only when the generated watch bundle
contains a `SentryDsn` value; the checked-in plist does not store a DSN, so
verify release-target injection in the generated project.

## Testing

The Swift package exposes portable buffering and transfer-cursor logic so it
can run on macOS without watch hardware:

```bash
cd packages/mobile/targets/DofekWatch
swift test --scratch-path ../../../../.context/dofek-watch-transfer-core
```

Keep SwiftPM output outside the Watch target's synchronized source folder.
SwiftPM's [`--scratch-path` option](https://github.com/swiftlang/swift-package-manager/blob/main/Sources/CoreCommands/Options.swift)
selects a separate build directory; otherwise Xcode includes the generated
files through [Apple Targets' synchronized folder](https://github.com/EvanBacon/expo-apple-targets/blob/main/packages/apple-targets/src/with-xcode-changes.ts).

The remaining recorder, transfer, lifecycle, and Watch Connectivity behavior
must also be exercised through the generated watchOS target. Validate sensor
capture and phone transfer on physical hardware; Simulator does not reproduce
all Core Motion behavior.
