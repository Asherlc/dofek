# Dofek watch app

The Dofek watchOS companion records motion and relative-altitude samples, then
queues compressed files for transfer to the paired iPhone. The screen shows
sensor availability, recording state, pending sample counts, phone reachability,
and manual recording and sync controls.

## Runtime behavior

- `CMSensorRecorder` collects accelerometer data, including supported
  background recording.
- `CMMotionManager` and `CMAltimeter` collect gyroscope and relative-altitude
  samples while the app is active.
- `TransferManager` merges nearby accelerometer and gyroscope samples,
  compresses the payload, and queues it with `WCSession.transferFile`.
- `WatchSessionDelegate` activates the session and handles requests from the
  iPhone companion.

Apple documents sensor availability and delivery constraints in
[Core Motion](https://developer.apple.com/documentation/coremotion). File
transfers between the watch and phone use
[Watch Connectivity](https://developer.apple.com/documentation/watchconnectivity).
The UI reports unavailable hardware instead of assuming every watch supports
every sensor.

## Project integration

`expo-target.config.js` declares the watch target, deployment target, bundle
identifier, and required frameworks for `@bacons/apple-targets`. The iOS project
is generated by Expo prebuild; do not edit generated Xcode project files. See
the [mobile development guide](../../README.md#ios-simulator-development-build).

`Info.plist` contains the target-specific motion usage description. Target
build settings come from `expo-target.config.js` through prebuild.
`DofekWatchApp.swift` starts Sentry only when the generated watch bundle
contains a `SentryDsn` value; the checked-in plist does not store a DSN, so
verify release-target injection in the generated project.

## Testing

The Swift package exposes portable buffering and transfer-cursor logic so it
can run on macOS without watch hardware:

```bash
cd packages/mobile/targets/DofekWatch
swift test
```

The remaining recorder, transfer, lifecycle, and Watch Connectivity behavior
must also be exercised through the generated watchOS target. Validate sensor
capture and phone transfer on physical hardware; Simulator does not reproduce
all Core Motion behavior.
