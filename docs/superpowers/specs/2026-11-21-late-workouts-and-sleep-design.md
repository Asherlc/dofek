# Late workouts and sleep

## Scope

Help people compare their recorded workout timing and cardiovascular load with the sleep that followed. Add opt-in evidence to the existing `get_recovery_training_series` MCP tool at `main_sleep` grain. Reuse its permissions, canonical records, and pagination. Use existing imported data and profile facts. A caller can inspect the nights contributing to each comparison and read the study's suggestion separately from personal observations.

The selected approach uses verified inputs. A separate approach would estimate elapsed zone intervals from irregular samples or estimate onset from sleep stage changes. That could extend coverage and would require its own rules, labels, and approval.

## Workout matching and heart-rate load

- Reuse the [pre-sleep workout matcher](../../../packages/server/src/repositories/pre-sleep-activity-repository.ts) and its preceding main wake requirement. Use the verified sleep onset as the upper boundary for this analysis. Require a complete workout inside that window. A workout crossing either boundary retains its source evidence and is unavailable for whole-workout analysis. Exclude the relaxation activities named in the study and workouts shorter than one minute. Deduplicate by canonical activity group before grouping nearby workouts. Keep `no_records` distinct from a confirmed zero load.
- Leota et al. grouped workouts logged within 60 minutes. The paper leaves the exact interval convention unspecified. For Dofek, group adjacent workouts with at most 60 minutes from the preceding end to the next start. Use the final recorded finish and count zone time inside the measured workout intervals. Apply the habitual-onset window to each grouped finish. If two independent bouts finish inside that window, return their evidence and leave the single-bout comparison unavailable. An independent bout outside the window does not make an in-window bout ambiguous. Withhold load for unresolved overlapping workouts. These are Dofek matching rules for applying the published measure to imported records. [Leota et al., Methods and Table 6](https://www.nature.com/articles/s41467-025-58271-x.pdf)
- Start with complete second-resolution workouts from the standalone `fit-file` importer. Require one unambiguous FIT member linked to the canonical group. Use that member's own valid session start and elapsed duration to establish bounds. Canonical group endpoints can combine different recordings, so they cannot establish the scoring interval. Fractional endpoints are ineligible for the initial one-second grid. The member ID, `fit-file` provider, and file source type establish recording provenance. Per-sample file and device identity are unknown. [FIT importer](../../../src/jobs/process-fit-file-import-job.ts)
- Count one recorded second per valid BPM sample on the complete half-open grid from start through the second before finish. Test completeness on the surviving canonical sensor observations. Equal timestamps count once through existing deduplication. Conflicts retained in the evidence, missing seconds, irregular streams, and source switches leave the load unavailable. Dofek's current WHOOP cloud importer requests a six-second step. WHOOP also documents that its consumer heart-rate zones can use reserve or custom cutoffs. [Garmin FIT recording modes](https://developer.garmin.com/fit/articles/cookbook/decoding_activity_files.html#smart-recording) · [WHOOP heart-rate zones](https://www.whoop.com/us/en/thelocker/more-personalized-heart-rate-zones-with-whoop/)
- Use an existing personal maximum heart rate where its meaning is established, or calculate Leota's published age-based estimate `192 − 0.007 × age²` from an existing birth date at the workout date. Return the value and its basis. A single workout's peak is a different measurement. A sample above the selected maximum leaves the recording unsupported for classification until its inputs can be reconciled. Both profile facts are nullable and current ingestion code offers no established population path. A user without either fact can still receive timing evidence. The study also permits automatically selecting a maximum from recorded heart rate. A Dofek rule for the eligible sources and observation history would need explicit approval before enabling that basis. [Leota et al., Methods](https://www.nature.com/articles/s41467-025-58271-x.pdf)
- Weight elapsed minutes below 50%, from 50% to below 60%, from 60% to below 70%, from 70% to below 80%, from 80% to below 90%, and from 90% through 100% of the personal maximum by 0 through 5, respectively. Apply the published category thresholds to the unrounded sum: light below 116, moderate from 116 to below 214, high from 214 through 461, and maximal above 461. Thirty minutes at 65% yields 60 points and falls in the light category. Start the sensor work from [`activity_sensor_sample`](../../../analytics/models/read_models/activity_sensor_sample.sql) and its attribution. Compute per-activity sensor aggregates in bounded incremental ClickHouse analytics. [Leota et al., Methods and Table 6](https://www.nature.com/articles/s41467-025-58271-x.pdf)

## Sleep onset and reference nights

- Keep the [selected main episode](../../../packages/server/src/repositories/sleep-episode-analysis.ts) and its source provenance. Populate actual onset from a documented source field that means detected sleep onset. Polar AccessLink's `sleep_start_time` is an eligible first source, and [the importer preserves it](../../../src/providers/polar/parsers.ts). The existing `providers` filter applies to both sleep and workouts. For example, `['polar', 'fit-file']` allows a Polar onset with a standalone FIT workout. The Apple Health XML and Oura session starts can represent in-bed or bedtime boundaries. They remain in the series as source observations with study onset unavailable from those fields. [Polar AccessLink sleep schema](https://www.polar.com/accesslink-api/#schemasleep) · [Polar Sleep Plus Stages white paper](https://www.polar.com/en/img/static/whitepapers/pdf/polar-sleep-plus-stages-white-paper.pdf)
- Calculate the arithmetic mean onset for the corresponding calendar month and weekday or weekend, including eligible episodes regardless of workout exposure. Use the same caller or profile analysis time zone for all nights, including travel. Polar sleep ingestion preserves the UTC instant and loses the original offset. Use the main-sleep wake date in that analysis zone as Dofek's convention for assigning midnight-spanning nights to a calendar group. Express onset relative to that wake date's local midnight before averaging, so onset at 23:50 and 00:10 for equivalent nights averages to midnight. Resolve the reference to an instant before calculating elapsed workout timing. Preserve the analysis time-zone provenance and leave unresolved daylight-saving wall times unavailable.
- Load observations across each intersecting calendar month so changing the requested date range or page cannot change the reference. Include only permitted, recorded reference nights and report their IDs, observed count, and the month and weekday/weekend group. Each date supplies one onset. When a date has multiple independent eligible main episodes, report that date as ambiguous for the reference and keep its episode observations. Keep a missing reference unknown. The study used retrospective data. A currently incomplete month describes the observed part of that month.
- Return the signed offset from habitual onset and the elapsed time from workout finish to actual onset. The study's primary exercise window is inclusive from 10 hours before to 2 hours after habitual onset. A workout may therefore finish after habitual onset and still precede actual onset. [Leota et al., Methods](https://www.nature.com/articles/s41467-025-58271-x.pdf)

## Output and interpretation

Return per-episode evidence containing matched workout and sleep identifiers, source attribution, recorded finish and verified onset, habitual onset and its reference nights, signed timing offset, elapsed interval to actual onset, actual onset's deviation from habitual onset, sleep duration where its source records time asleep, and eligible workout load with its category. Expose an explicit unavailable reason for each unsupported input. Count dates with one unambiguous in-window bout and valid timing across the full filtered range before pagination. The measured-load count is the subset of those dates with a supported score. Keep eligible out-of-window timing visible as context. If independent episodes share a wake date and both would contribute, retain their individual evidence and exclude the date from the night counts.

The user-facing evidence describes personal observations. Report the study suggestion separately, with a citation and its population context. The authors suggest trying an earlier finish or lighter exercise close to sleep. Their population model used additional covariates and a highly active adult WHOOP cohort. The tool serves descriptive observations, and its first version uses verified onset and total sleep duration as the outcomes. [Leota et al., Results, Discussion and Methods](https://www.nature.com/articles/s41467-025-58271-x.pdf)

## Acceptance and implementation order

1. Prove the eligible FIT import and Polar onset paths with synthetic source-shaped records. Verify preserved recording attribution, real workout start and finish, sleep onset, and account isolation. Establish a positive end-to-end fixture with an explicitly present maximum heart rate or birth date before making the feature available.
2. Add failing tests for zone and category boundaries, the published 30-minute example, missing personal maximum, age-derived provenance, a fully covered zone-zero workout, fractional endpoints, differing canonical and FIT bounds, missing or invalid samples, duplicate timestamps, irregular recording, unresolved overlap, and source switches. Verify touched database behavior against the repository's real engines.
3. Add failing tests for the published exercise window, the 60-minute grouping edge, independent in-window and out-of-window bouts, date scoping, a workout crossing the prior wake, missing prior wake, unknown onset, after-midnight and month-boundary onset, two main episodes on one date, travel provenance, daylight-saving transitions, and calendar reference stability across pages and partial date selections.
4. Add the opt-in MCP evidence and verify the usual tool path with both permission scopes, contribution counts, and a source change. Document eligibility and interpretation in the existing MCP guide. Run repository lint, workspace typechecks, focused noninteractive tests, and the relevant real-engine integration tier before pushing the implementation.

The recording grid, nearby-workout grouping convention, and wake-date convention are specific design decisions for review. The published code fits models from already prepared timing and load values. [Archived analysis code](https://zenodo.org/records/14933997)
