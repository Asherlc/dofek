# Running race-time forecast

Dofek will import existing Runalyze race finishes through the shared personal-token connection and expose a read-only 10K and half-marathon forecast with its source race. Runalyze Supporter and Premium accounts can read race results with a personal token. Its published race result contract includes distance in kilometers, finish time in seconds, date, completion status, and a linked activity ID. The endpoint is marked alpha. The live unauthenticated endpoint returned HTTP 401. An authenticated result has yet to be checked. [Runalyze Supporter OpenAPI](https://runalyze.com/doc/api/supporter) · [Personal API](https://runalyze.com/help/article/personal-api)

The forecast uses `finishSeconds × (targetMeters ÷ sourceMeters)^1.07`. The study found reasonable calibration for 10K and half-marathon predictions and used shorter reported races. Use the studied shorter race distances of 5 km, 5 miles, 10 km, and 10 miles where the imported distance identifies them exactly. A recent race at comparable fitness is the study context. The API returns the source date so the caller can assess recency. Course conditions and effort intent remain unknown. The output is an estimate from the recorded finish. [Vickers and Vertosick](https://doi.org/10.1186/s13102-016-0052-y) · [Study questionnaire and calibration](https://static-content.springer.com/esm/art%3A10.1186%2Fs13102-016-0052-y/MediaObjects/13102_2016_52_MOESM1_ESM.docx)

Use the linked activity's explicit running sport and keep ambiguous or unmatched activities out of the forecast. Runalyze exposes the linked sport name and allows account-specific custom names. Begin with its documented Running name, matched case-insensitively, and preserve the source label. Take both numeric inputs from the same completed race result. [Runalyze activity schema](https://runalyze.com/doc/api/supporter) · [Runalyze sport setup](https://blog.runalyze.com/allgemein-en/how-to-setup-your-account/) · [Custom sports](https://runalyze.com/help/article/adjust-sport-mapping)

Store race results as account-owned source facts. A workout row represents the tracking session and can already be present through another provider. A race finish is a distinct result and its date and elapsed time need no synthetic workout timestamps. Compute estimates on read in the authorized MCP activity tools. Reuse the provider connection and sync workflows, including token handling, correction, and deletion. Use whole successful result inventories so missing entries can be reconciled safely.

Runalyze is the first source because its account-scoped API can supply both race values and a linked sport from existing recorded data. Athlinks offers profile result history behind an app credential. RunSignup offers event metadata and public result sets, with results split by events. Both require additional app-side lookup or account matching. [Athlinks athlete API](https://api.athlinks.com/athletes) · [RunSignup event results](https://runsignup.com/API/race/%3Arace_id/results/get-results/GET)
