# MCP CIMD Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let compliant MCP clients use HTTPS Client ID Metadata Documents for Dofek OAuth while preserving Dynamic Client Registration for legacy clients.

**Architecture:** A focused CIMD resolver implements the SDK registered-client store interface alongside the encrypted DCR store. It validates and fetches a client metadata URL only when the client ID is a qualifying HTTPS URL, safely resolves it to metadata, and caches valid results. A custom authorization-server discovery handler extends the SDK metadata with CIMD support because SDK 1.30.0 parses the field but exposes no server-router option for it.

**Tech Stack:** TypeScript 6, Express 5, Zod 4, Vitest, `@modelcontextprotocol/sdk` 1.30.0, `ipaddr.js` 2.5.0, Node `dns` and `https` APIs.

**Spec:** `docs/superpowers/specs/2026-08-31-mcp-cimd-design.md`

## Global Constraints

- Upgrade the MCP SDK to exactly `1.30.0` and add `ipaddr.js` exactly `2.5.0`, the current stable releases verified on 2026-08-31.
- Retain DCR and its encrypted persisted client secrets; CIMD must not write to the database.
- Treat every supplied CIMD URL as untrusted; accept only public HTTPS destinations and send no credentials.
- Validate `client_id` equality and existing redirect-URI policy before an OAuth flow uses CIMD metadata.
- Add unit tests next to each new production source file. Keep the existing real-database OAuth integration suite for DCR; do not weaken the public-host requirement to manufacture a CIMD integration test.
- Preserve `paseo.json`, which is unrelated and untracked in this worktree.

- [ ] **Step 3: Implement a bounded SSRF-safe metadata fetcher**

Implement:

```ts
export const CIMD_CACHE_MAX_AGE_MS = 86_400_000;
export const CIMD_FETCH_TIMEOUT_MS = 5_000;
export const CIMD_MAX_RESPONSE_BYTES = 65_536;
export function isCimdClientId(clientId: string): boolean;
export class McpOAuthClientMetadataResolver {
  async getClient(clientId: string): Promise<OAuthClientInformationFull | undefined>;
}
```

Add `ipaddr.js` `2.5.0` as a direct server dependency. Require absolute HTTPS URL, hostname, and non-root path; reject credentials, query, and fragments. Resolve using `dns.promises.lookup(hostname, { all: true, verbatim: true })`; use `ipaddr.js` range classification to reject every non-`unicast` IPv4/IPv6 address; connect only to a validated IP with Node `https.request()` while retaining the original host for TLS SNI and HTTP `Host`. Send no credentials, reject 3xx responses, use a 5-second timeout that destroys the HTTPS request on expiry and clears on every terminal path, JSON `Accept`, and a 65,536-byte streaming response limit. Require a JSON response; parse `OAuthClientMetadataSchema`; require exact client ID equality; require `token_endpoint_auth_method === "none"` when specified; reject client secrets; and validate every redirect URI using `isAllowedMcpOAuthRedirectUri()`.

Cache only valid metadata. Respect a shorter `Cache-Control: max-age`, cap it at 24 hours, default to five minutes, and never cache failure.
