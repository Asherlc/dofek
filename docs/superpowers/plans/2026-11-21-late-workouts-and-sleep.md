# Late workouts and sleep implementation plan

> For the Paseo Implementer, use the test-driven-development skill and implement the assigned tasks in order. Send the failing and passing check output and any architectural uncertainty to the lead. The lead reviews each diff before the next task or push.

**Goal**. Show recorded workout finish, habitual and actual sleep onset, time asleep, and supported heart-rate-zone load on the existing Dofek Sleep screen.

**Architecture**. Reuse the reconciled sleep episode selection and preceding-main-wake workout matcher. Build a bounded, protected Sleep procedure that returns display-ready observations. Compute expensive FIT sample coverage once per canonical activity in ClickHouse and apply the study's zone weights to its compact BPM counts on the server. Web and iOS render the same observations and disclosure.

**Stack**. TypeScript, Zod, tRPC, PostgreSQL, ClickHouse/dbt, React, React Native, Vitest, and Storybook.

**Spec**. [Approved design](../specs/2026-11-21-late-workouts-and-sleep-design.md) and [Paseo Canvas artboard](../../../design/late-workouts-and-sleep/evidence.html).

## Constraints and review focus

- Use Sleep Insights on web and the existing Sleep screen below Recent Nights on iOS. Use a single in-place View nights disclosure, with existing style and accessible controls. Keep product query, test, and Storybook parity.
- Use existing import and profile data. A heart-rate gap or absent profile facts cannot become zero activity or a load category. Preserve timing when load is unsupported.
- Separate the study suggestion from the observations, keep outcome comparisons descriptive, and retain reasons and source evidence for excluded nights.
- Apply the date entitlement before reference aggregation and matching. Exposing a prior wake, activity, or reference night outside access is a privacy regression. User/timezone/range changes must affect cache identity.
- Cover one-second FIT geometry, canonical-member conflicts, exact grouping and timing boundaries, sleep source changes, end-of-month and repeated daylight-saving times, plus stale-data and error states on both platforms.
- Use the existing workspace and current branch. Keep pre-existing design-guide edits out of changes. Use RTK and repository commands. Keep required gates and understand a failure before changing behavior.

## T06. Calculate verified load and serve the Sleep procedure

Files are new `analytics/models/read_models/activity_fit_heart_rate.sql` and colocated real ClickHouse test; new `packages/server/src/repositories/late-workout-sleep-repository.ts` and tests; `packages/server/src/routers/sleep.ts` and its integration tests; and new shared response schema `packages/training/src/late-workout-sleep.ts` for the server and both clients. Register the selected range endpoint in `packages/server/src/lib/date-window.ts` and the shared package subpath using existing workspace conventions.

- [ ] Add the red real ClickHouse tests for the eligible recording and corrections. A `fit-file` member with a valid FIT session and 1,800 distinct whole-second reported BPM observations from `[start, finish)` returns 1,800 seconds at 130 bpm. A point exactly at finish contributes zero. A missing second, off-grid sample, source switch, fraction at a FIT bound, two eligible FIT members, or a wrong member cannot produce complete evidence. The canonical group may extend beyond both FIT endpoints without refitting the workout. A source correction or deletion must replace or invalidate previously complete evidence.
- [ ] Implement `activity_fit_heart_rate`, one row per canonical activity, from `activity_sensor_sample` and live FIT source bounds. Keep both canonical and FIT member IDs, source bounds, valid covered seconds, status, compact `[(bpm, seconds)]`, and the lifecycle/version evidence needed to reject stale/mismatched rows. Use the existing bounded dirty-key and build patterns. The route reads targeted model rows by current user and candidate groups and checks the active member and its original session bounds. Keep the expensive sensor scan off the request path. Establish a fixture derived from the FIT ingestion shape and keep distinct member and corrected-source cases in the real model suite.
- [ ] Add red server tests for `sleep.lateWorkouts({days, endDate})`. A user with maximum 200 bpm, 30 minutes at 130 bpm, and a matched Polar night yields 60 points and light load. Cover exact 50%, 60%, 70%, 80%, 90%, 100% and excess BPM, zero with complete zone-zero coverage, 116/214/461 point boundaries, missing max and birth date, and age-35 provenance with max 183.425 bpm. An age-derived result is labeled as estimated maximum and a measured point above max suppresses scoring. A grouped bout sums member scores before applying a category and requires supported complete heart-rate evidence for every constituent workout.
- [ ] Implement `LateWorkoutSleepRepository.list({days, endDate})` and the protected, cached Sleep route using `lateWorkoutSleepSchema`. Produce `{range, matchedNightCount, measuredLoadNightCount, axis, nights}`. Each night has `episodeId`, `date`, `sleepProvider`, `workouts` with canonical IDs, optional FIT source member IDs plus type/finish, `status` and reason, `habitualOnset` with date-group, reference date and episode IDs, `actualOnset`, `durationMinutes`, `finishOffsetMinutes`, `actualOnsetOffsetMinutes`, `minutesFromFinishToSleep`, `load` with nullable score/category/max basis/coverage and reason, and nullable plot positions. The full range counts each valid wake date once. A measured-load count must also count in matched timing. Start with the published offsets -600/+120 as axis endpoints and extend only to fit matched observations, computing positions on the server. Cap All and long inputs at 366 and intersect the account access window. Read full permitted months intersecting the result range plus the matcher's accessible two-day preceding-wake context. Empty intersections and completed reads with no observations produce explicit empty data. Propagate real query failures.
- [ ] Verify the normal tRPC path with FIT and Polar-shaped fixtures and source/provider overlap, account-scoped range boundaries, duplicate wake dates, matched timing without load, and unsupported or stale sensor evidence. Run real PostgreSQL and ClickHouse tests through `rtk pnpm test:integration -- <paths>`, targeted unit tests, `rtk pnpm lint:analytics-sql`, and `rtk pnpm lint:analytics-policy`. Review the complete server slice before committing and pushing.
